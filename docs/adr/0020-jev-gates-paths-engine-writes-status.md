# Jev gates which engine path runs; the engine writes status; thresholds are per action

The engine decides several things a person would judge at a glance by matching strings: whether a pane shows an agent waiting, whether an exit with no Outcome was a crash, which ticket a reject note names. Issues #42, #62, #71 and #104 were each one of those matches being wrong (the survey is issue #114, https://github.com/BillyLuisNeedham/agents-console/issues/114). TypeSafe's Jev is a judgement model: it takes one Evidence object and a set of narrow typed questions and returns a Judgement per question with calibrated probabilities, never generated text, in about 150ms. Issue #105 (https://github.com/BillyLuisNeedham/agents-console/issues/105) adds the port every later call site shares (`engine/jev.ts`).

We decided on one rule for every call site that follows. A Judgement only gates which engine path runs: the engine remains the only writer of state and status (ADR-0005, `docs/adr/0005-engine-owns-final-status.md`), so an answer selects between paths the engine already has, and never becomes a status by itself. The threshold for acting on an answer is set per action, where the consequence of being wrong is known, never as one global number; the docs' guidance is roughly above 0.9 to act unattended and below 0.5 to route to the human. And a pool without Jev behaves exactly as it does today: the key is read once at the CLI boundary (`engine/server.ts`), an absent key gives the pool an unconfigured port, and every ask that cannot be answered, for any cause, comes back as a fallback rather than an error, so the call site takes the heuristic path it always had and the pool keeps running offline. Each cause is logged once, when it first bites and again only when it changes, not once per call.

The alternatives were a global confidence threshold (one number cannot fit both "record a crash" and "pick a ticket to reject") and letting Jev write status directly (which reopens the two-writers problem ADR-0005 closed). Consequences: the SDK is the engine's first runtime dependency and is constructed with every option explicit so it never consults the environment itself; the SDK's own defaults stand for timeout and retries (10 seconds per attempt, two retries), so a dead API can hold one ask for around 30 seconds before the fallback, accepted until it proves a problem; and a test (`engine/boundary.test.ts`) now enforces the boundary rule the code had only stated in a comment.
