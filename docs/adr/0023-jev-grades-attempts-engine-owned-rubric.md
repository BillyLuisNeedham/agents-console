# Jev grades Attempts when a key is present; the rubric is engine-owned, versioned and recorded on every Grade

Amends ADR-0006 (`docs/adr/0006-verify-separate-grading-hybrid-selection.md`). That ADR deferred the verifier paper's logprob-expectation trick because no logprob-capable endpoint was to hand, and settled for a grader agent returning a plain 0 to 10 score. Jev's Score is that deferred mechanism: an expected position over a described rubric, with a probability per level and a confidence, in one request of about 300 ms for a few thousandths of a cent. ADR-0020 (`docs/adr/0020-jev-gates-paths-engine-writes-status.md`) gave the engine the port. A live bench on 2026-09-20 against four real Attempts and one constructed probe (`docs/research/jev-grader-bench/REPORT.md`) showed identical verdicts across repeats, scores moving at most 0.2 between identical runs, and the template's trust rule firing at 0.9 or above when a summary claimed passing tests over a log that showed a failure.

We decided that when the pool has a key, Jev **replaces** the grader Attempt: no grader tickets spawn, no grader node cards appear, and the Grade `{ score, verdict, reasons }` is composed in engine code from typed Judgements over one Evidence object per Attempt. Without a key nothing changes. The Grade keeps its shape and Selection is untouched (same 2-point margin, same head-to-head spawn), because the bench's passes clustered at 7.2 to 8.4 and its flags at 3.4 to 5.1, which the existing margin already separates. The rubric is several narrow Jev Scores, never one wide scale, following the docs: `ticket_fit` (five levels, weight 0.4), `claim_fidelity` (four levels, 0.3), `log_health` (four levels, 0.3), each normalised by `levels - 1` and weighted into 0 to 10. Beside them sit gate Nouls phrased so that yes is the flag case: `contradicted_claim`, `untouched_criterion`, `failing_at_end`, plus a code-derived gate from two single-hop Nouls (`summary_claims_tests_pass` and `failing_at_end`). Any gate at or above 0.6 forces `verdict: flag` regardless of the weighted score, because a weighted mean would average a confident contradiction into silence; that is how the template's rule, "the log is evidence, the summary is a claim, when they disagree the log wins", survives the move to a model that does not treat Evidence as hostile. `flag` also applies below 6.0. `reasons` is fixed phrases keyed by rounded level and fired gate; Jev generates no text. The exact wording, weights, thresholds and composition live in one versioned unit in engine code (`docs/research/jev-grader-bench/rubric.ts` is the benched source), not in the Pool's `verify.md`, which from now on serves only the fallback grader agent. Every Grade records the rubric version, the response's model id and the Evidence budget used, so a score always says which instrument produced it.

Evidence is the changed lines only (`git diff -U0` over the same range the Attempt diff uses today) plus the last 20,000 characters of the ANSI-stripped log, with the Ticket text and the agent's summary under a field named `agent_summary_claim`. The bench showed the diff is essential (without it ticket-fit confidence fell to near zero) and more log is distractor (a 40,000-character tail changed nothing). When `ticket_fit` confidence is below 0.5 and the Evidence was trimmed, the engine widens once to the full-context diff and an 80,000-character tail if that fits, then accepts the Grade, marks it low-confidence and flags it; low confidence on the other two dimensions is marked in reasons only. Low confidence never falls back to grader agents: two instruments in one Selection are not comparable, the very point ADR-0006 made about two grader calls. Jev unreachable for any cause does fall back to spawning the grader agents for that round, as ADR-0020 requires.

The alternatives were a single 0 to 10 Jev Score matching today's grader (the docs advise against one wide scale and the bench's confidence would have been meaningless), gates as one Choice (a Choice is relative and settles which option, while each gate is an absolute condition that can be false for all of them), Nouls alone with no Score (Selection needs a rank), an operator-editable rubric file per Pool (a Score rubric is a calibrated instrument, not a prompt: reword one level and the 6.0 line, the 0.6 gate line and the low-confidence rule silently stop meaning what they meant, so drift is tolerable only with provenance and a later Pool override may append per-criterion gate Nouls but never edit levels), and a two-pass summarise-then-grade Evidence strategy (Jev returns no text, and its select-then-grade form failed at exactly the size it was meant to rescue). Consequences: a Pool that hand-tuned `verify.md` keeps that tuning on the fallback path only, and the recorded rubric version makes that visible rather than silent; the port pins the `jev-latest` alias today and must pin a versioned model id once thresholds are set, re-running the bench (about 54 requests, four cents) on each deliberate bump; `claim_fidelity` is the weakest question (confidence 0.09 to 0.65 on clean work) and the first follow-up narrows it to diff-only claims; and no agent-grader baseline exists yet, so this ADR claims stability and cost, not superiority.
