# Vitals are client-polled worktree/log reads, not engine events

Ticket-card Vitals (diff totals, time since last observable change, sparkline) are read by the Console client polling `GET /api/activity?ticket=<id>` on a ~2s interval for each ticket with a live attempt, never from engine events and never from the SSE snapshot stream. The snapshot stream is engine-event-driven and goes silent whenever the pool waits at an interrupt — exactly the moment a wall-clock staleness signal must keep ticking — so Vitals cannot ride it. The server computes each response on demand from the attempt's worktree (`git diff --numstat HEAD`, plus untracked files) and the attempt log's size/mtime, with a 1s in-memory cache per ticket; the engine's only contribution is recording `cwd`/`branch` on `spawned` and `resolver` events so a ticket maps durably to its worktree. A side effect: Vitals need no engine cooperation and no state channels, and survive a server restart unchanged.

**Amendment (issue #157)**: the response is no longer cached whole. Only the worktree diff, the one part that runs git, is cached per ticket, for 1.5 s from when it lands, just under the client's 2 s poll, so one tab sees each poll fresh while a second tab or a burst shares the read; a read in flight is shared by every request that arrives while it runs. The diff runs git and reads the untracked files without blocking the server, which serves every other request meanwhile. `running` and the log and event reads are fresh on every request.

**Amendment (issue #161, ADR-0032)**: Vitals are no longer polled by the client. The server runs one check every 2 s for all tabs, and only while at least one tab is visible. It calls the same cached activity read for each candidate (in progress, at a checkpoint, or with a live resolver), and skips a candidate whose last read said nothing was running until the snapshot moves it. Each tab gets only the values that changed, in a `live` frame on its WebSocket. Hidden tabs get nothing until they become visible again, and then they get the whole cache. The Console's own 2 s tick stays, with no network: it moves the "Ns ago" copy and adds the sparkline sample. What survives of the original decision is that Vitals are worktree and log reads, not engine events. `GET /api/activity` stays for other callers.
