# Stop is offered in any phase, and leaves the panes running

ADR-0019 offered "Stop server" only once a pool was `done`, and `POST /api/stop` refused every other phase with 409, on the grounds that an attempt mid-flight or an answer about to be given must not be ended by a stale tab or a stray curl. In practice the operator who wants a server gone mid-run has had to find the terminal it was launched from, or use Restart (ADR-0026), which is allowed in any phase but brings the server straight back. Restart's shutdown is the same one Stop takes, and it already proves that stopping a live pool loses no terminal-backed work.

We decided that Stop is offered in every phase while the Console is connected, a pool that has not started yet included: it is the kill switch for the server, not a judgement on the run. `POST /api/stop` and the socket's `stop` request accept in any phase with 202, and a repeat during a stop under way is acknowledged again, as before. The control moves from the canvas header into the Settings pane's footer, on the left, opposite Restart on the right, so the two ways of ending this server sit together; the header no longer carries one.

Stopping a live pool leaves the world as a Restart leaves it before its relaunch. Shutdown never closes or kills a herdr pane: a terminal-backed Live attempt, a Held pane, an enlisted pane and a live Conversation all keep running in herdr, and the next boot of the same pool (`agent-console <poolDir>`) reconciles them as it does after a Restart (ADR-0014, ADR-0018's issue #140 amendment). Headless attempts are the exception ADR-0017 already made: their stdout dies with the engine, so shutdown stops them and the next boot runs their Tickets again.

Because a live Stop leaves something behind, its one inline confirmation says what: "Stop server? 3 Tickets and 1 Conversation keep running in herdr; relaunching picks them up.", counted from the snapshot with the zero parts left out, and for a headless pool's live Tickets that they stop and run again on relaunch. A pool with nothing live keeps ADR-0019's "Really stop?". It is still one inline step, not a modal: the stop loses nothing that a relaunch cannot pick up, so a second gate would only slow the operator down.

**Consequences**: ADR-0019's done-only gate and its 409 refusals ("pool is <phase>, not done: stop refused", "pool not started: nothing to stop") are gone; its farewell, the `stopped` phase, the relaunch notice and the socket's 1000 `stopped` close stand. A stop before the pool starts sends no `stopped` snapshot, since there is no run to send one; the sockets still close with 1000 `stopped`. A stale tab or stray curl can now stop a running server, which costs a relaunch and nothing else.
