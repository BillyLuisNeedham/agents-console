# Attempts spawn as named herdr tabs, not anonymous panes

ADR-0014 settled that a `terminal: herdr` pool runs every attempt in a herdr pane created via the socket API, always unfocused. Prototyping the Console surface (issue #29, `prototype/console-terminal-surface/`) refined that: the attempt-terminal unit is a whole named **tab**, not a bare pane. Each spawn site (implement, merge resolver, verify grader, head-to-head judge) opens its own tab via `tab.create` with `label` = `<ticket-id> · <ticket-title>` (capped at 40 characters), `focus: false`, and `cwd` = the attempt's worktree, so the operator's tab bar reads as the roster of tickets in flight and a spawning ticket never steals terminal focus. `tab.create` returns no root pane id (verified herdr behaviour), so the engine recovers the pane id from `pane.list` filtered by the created tab's id and records it on the attempt's `spawned` event as `pane_id`; the Console's peek/focus endpoints (issue #29) key off that recorded id. Herdr stays optional exactly as ADR-0014 promised: a daemon that is absent or misbehaving never blocks the spawn; the attempt falls back to headless for that run and the spawned event carries `pane_id: null` plus a `terminal_error` fact, so the fallback is visible on the ticket log. What executes inside the tab (the wrapper-shell run, `pane_exited` wait, reconciliation) remains ADR-0014's engine work, unchanged by this refinement.

**Considered options**: naming the tab after the ticket was the point of the feature, and the ticket title (the Issue file's first heading) is the only human-readable name the engine already has; no separate display-name field was added. `pane.split` was rejected for creation because it ignores `cwd` for workspace placement (verified prototype finding) and produces anonymous splits, which is the problem this refines away. A generated monotonically increasing label was rejected: the mapping from tab to ticket must be obvious without memorising ids, and the spec's user stories demand `<ticket-id> · <ticket-title>` verbatim.

**Verified herdr quirks (live against herdr 0.8.2, prototype)**: three behaviours the prototype confirmed by observation and the implementation must not rediscover by debugging. (1) `pane.read`'s `revision` does not advance reliably — verified stagnant at 0 while output grew — so freshness never comes from the revision counter; a caller re-polls and diffs the returned text. (2) A literal `\r` inside `pane.send_input` text is pasted data, not a submit (bracketed-paste semantics, verified); submission requires the command line as printable text plus `keys: ["Enter"]`. (3) Reads against a background (unfocused) tab return empty for the first seconds after `tab.create` because herdr warms up viewports lazily (verified); an empty read means "waiting for output" and must be treated as such, never as an error. Two more, verified against herdr 0.8.2 while fixing issue #61: (4) a closed tab takes its panes silently: `tab.close` pushes one `tab_closed` (carrying `tab_id`, no pane id) and no `pane_closed` for any pane in the tab, whereas `pane.close` does push `pane_closed`, and a shell that exits pushes `pane_exited` and then its tab goes with no further event; a wait on a pane's end must therefore also subscribe to `tab.closed` and re-check `pane.list` when one lands, which is safe because the listing drops the panes before `tab.close` is answered and the `tab_closed` push trails that answer by tens of milliseconds (verified six of six closes). (5) `events.subscribe` replays retained history before live events: a fresh subscriber first receives the daemon's backlog of past events, paced at about one per 100ms, so a subscriber must filter by id and treat a replayed end for its own pane as the real end it missed.

## Amendment (issue #94): tabs open in the Pool workspace, and attempts report their agent identity

Tabs created with `cwd` alone land in whatever herdr workspace the daemon's focus happens to be in, so one pool's attempt tabs scattered across the operator's projects. Every `tab.create` now names a **Pool workspace** (CONTEXT.md): the one herdr workspace a Terminal-backed pool opens its attempt and Conversation tabs in. The engine resolves it once at boot, in a fixed order — the id the pool remembers in `runs/pool-workspace.json`, else the workspace the server was launched in (`HERDR_WORKSPACE_ID`, read by the server CLI and passed down as an option; nothing below that boundary reads the environment), else one created for the pool via `workspace.create` labelled with the pool directory's name, in the pool's checkout and unfocused. Each remembered or launch candidate is confirmed with `workspace.get` before it is used, so an operator who closed the workspace between runs falls through to the next step rather than spawning into an id that no longer exists. There is deliberately no path matching against `workspace.list`: a workspace's cwd is the operator's to change, and two pools of one repo would collide on it, so identity comes from an id the pool recorded or was told, never from a guess. The resolved id rides to every spawn site through the Attempt environment (ADR-0014's pattern: one place decides, every site reads), and boot reconciliation's `pane.list` is scoped to it, so a pool's orphan check no longer sees the whole host's panes. The workspace is never closed at shutdown and never focused when created.

Two failures have decided fates. If no Pool workspace can be resolved at boot at all, the pool boots anyway and every spawn takes ADR-0014's per-attempt headless fallback: a `tab.create` with no workspace id is never sent, because an unplaced tab is the scattering this change exists to stop. If a `tab.create` is refused mid-run (in practice: the operator closed the workspace while the pool was running), the engine re-resolves once, persists the new id, notes it on the pool log, and retries the tab once; a second refusal is the same headless fallback as before.

The pane id no longer comes from a `pane.list` scan. herdr protocol 20 answers `tab.create` with `tab_created { tab, root_pane }`, both required, so the engine reads `root_pane.pane_id` directly and refuses an answer that carries none, exactly as it refuses one with no `tab.tab_id`. That removes the scan's race — a listing that had not yet caught up with the newly created tab — along with a call per spawn.

Finally, attempts now appear in herdr's left-hand agent list. herdr lists a pane there only when an agent is bound to it, and its own process-name detection never binds ours, because the harness runs inside `script` (ADR-0016). So the engine asserts the identity itself: `pane.report_agent` under source `herdr:agent-console`, with the resolved harness as the agent name, the attempt's tab label as the message, and a monotonic `seq`, sent once the wrapper has landed in a fresh pane and again for a boot-re-adopted orphan (herdr forgot what the dead engine reported); `pane.release_agent` at the Attempt ending, so a crashed attempt's tab, which stays open until merge, is no longer an agent at work. A Conversation is the one Attempt with a Turn state, so it is the one whose reported state moves: `working` while the agent works, `blocked` while it waits on the operator, herdr's word for "a human is what it needs". Every report and release is best-effort and swallowed: the sidebar is a convenience and never a dependency, exactly as the tab closes already were.

## Amendment (issue #100): a Pool workspace the engine created carries the Pool title

A Pool workspace created via `workspace.create` is now labelled with the **Pool title** (CONTEXT.md) rather than the pool directory's name, which stays the label for a Pool with no title. When the title changes, whether saved from the Console's Pool settings or edited while the Console was down, the engine relabels that workspace with `workspace.rename`. It relabels only a workspace it created itself: the launch workspace, and any workspace the pool remembers without having made it, keep the operator's label. So `runs/pool-workspace.json` now records whether the Console created the workspace and the label it last gave it; a file written before this amendment records neither, and its workspace is left alone rather than guessed about. A relabel is best-effort like every herdr call here: a refusal is a pool log line and the workspace keeps its label.
