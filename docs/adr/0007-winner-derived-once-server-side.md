# Winner is derived exactly once, server-side

A graded ticket's winner showed up in two places with two derivations: the grades endpoint picked the card's grade from the events file, and the Detail's winner badge keyed on the `merged` event. They drifted twice. First the endpoint took the last `graded` line, which parallel graders append in completion order, so the card could show a loser's grade while the badge sat on the merged attempt. Then the endpoint learned to key on `selected`, but the badge still keyed on `merged` — and the engine appends `selected` before merging, so a conflicted winner merge that checkpoints leaves the card showing the winner's grade while the Detail marks no winner for as long as the checkpoint sits unanswered. The decision: the winner is derived exactly once, in the grades endpoint, as the attempt named by the last `selected` event, and every UI surface reads it from there. The `merged` event survives only as the fallback for tickets graded before the selection machinery existed, whose files carry no `selected` event. Two local derivations drifted twice; one derivation cannot drift.
