# The Factory runs a Plan the operator builds, not a fixed recipe

Supersedes ADR-0037 (`docs/adr/0037-the-factory-is-an-engine-owned-recipe.md`). That ADR fixed the Factory as one run of Stations: the Grill, then Rounds of Implement, Prove, Review and Decide, then the Finish. It rejected "a user-defined Station graph" as a graph editor nobody needed yet. The Horde Plan Mode prototype (`prototype/horde-plan-mode/index.html`, deleted once the feature was built and last tracked at ebfe7c7) then laid out the operator's own flows and those of the authors whose skills he runs (Matt Pocock, Pstack, PClaude, Addy Osmani), and none of them fit the fixed order. Several begin with a talk and have more talks along the way. Several fan out over a list of tickets or findings. Several have human approval points the recipe has no place for. The engine pieces they need already exist: Tickets, `blocked-by`, worktrees, the serialised Merge queue, its resolver, checkpoints and Notices. What was missing was a way to say which piece follows which.

**A Line runs a Plan.** A Plan is a graph of nodes and edges, saved as a file. A node is a Conversation node, a Ticket node (of kind Agent, Prove, Review or Decide), a Merger, a Gate, or the one Finish. An edge routes one typed verdict from one node to the next. A loop edge may carry a Loop cap. The engine freezes the Plan into the pool when the Line starts at Boot, and from then on it reads the verdicts, keeps the counts and writes the next Tickets and Conversations itself. "Factory today" is a built-in Preset that reproduces ADR-0037's Line, beside one Preset for each author's own flow. Presets are compiled into the binary and read-only. The operator's own Plans live in the Plan library under `~/.agent-graphs/plans/`, and editing one never changes a Line already running.

**The engine still owns the routing.** These parts of ADR-0037 stand. Agents never propose the next node: an Outcome carries a verdict typed by its node's kind, and items when its node makes them, and the engine routes on them. A Ticket whose Outcome has no valid verdict checkpoints with "no verdict"; the engine never guesses. Ticket nodes write ordinary Tickets, so Resume, Keep talking, Close and Reassign all work on them. A follow-up proposed from inside a Line is held for the operator unless its node says otherwise, because what lands merges into the Line's branch. Decide writes the report. In a pool that runs a Line, approving the Finish is the Review, and the run-wide Review does not fire. The Steward never answers the Finish.

**The Rust core owns the Plan.** One module parses and validates the file, applies typed edits and re-validates the result whole, and runs every rule of a Line. The Console's editor holds a draft Plan and asks the engine to validate it; there is no second set of rules in TypeScript. The prototype's text command language is dropped, and the Steward's plan edits go through the same typed verb as the operator's. Validation is where the Plan's shape is enforced. Each edge's verdict must belong to its node's kind. Every cycle must hold a capped edge or pass through a person. A Merger folds exactly one per-item node.

**Per-item copies, not best-of-N.** A Ticket node runs one copy per pass, or one copy per item it is handed, with at most its cap live at once and the rest queued until a copy ends. Two copies never build the same thing; that is Verify's job, and Verify is unchanged. A Merger after a per-item node hands the pass on once every copy is done and merged, over the existing Merge queue: there is no second merge path, and Prove still checks merged work (ADR-0038). The Merger owns the conflict setting, a resolver on its own Assignment or a wait for the operator. Removing it is the opt-out, and each copy then hands on alone.

**People wait on hold Tickets.** A Gate, a spent loop and the Finish each wait as a hold Ticket, which is a Ticket no agent runs, raised as an Interrupt: today's Finish checkpoint, generalised. Resume opens it, Resume with notes sends `revise`, and Close sends `closed`. One answer path serves them all, with one Steward check and one Console form. Approving the Finish while anything still runs, queues or waits is refused with the list. The Finish's act (none, draft PR, PR, fast-forward, or free text) runs after the approval, from a Finish Ticket on the Finish node's Assignment. It no longer runs from Decide, so a Plan with no Decide finishes the same way and nothing leaves the pool before the operator says so.

**Settings live in the Plan.** Each node carries its skill, its Assignment and its note. An empty Assignment field falls through to the pool defaults when the Ticket is written. The Factory settings layers ADR-0037 introduced are deleted: the Stations' block in the Machine defaults and the Pool settings, their limits, and the Console's Factory fields. A Line brief may still override a node for its own Line, and the override is applied as a plan edit to the frozen copy.

**Considered Options**: Keeping the fixed recipe and adding Plans as a second mode was rejected: two routing engines, and the fixed one is the special case of the other. Keeping the Grill outside the graph, so that Boot opens it and Start the Line begins the Plan after it, was rejected because several authors' flows have talks in the middle too. Items as files the node writes and the engine globs were rejected in favour of the Outcome, which is already validated at the boundary. A merger that is a real agent merging the copies' branches itself was rejected as a second merge path beside the Merge queue. A merger as a setting on the per-item node, with no node of its own, was weighed and rejected: the Merger is what the operator sees and removes, and the editor places it for them.

**Consequences**:
- Ticket ids are readable node ids with a pass number: `implement-1`, `build-2.3`, `approve-1`, `finish-1`. The Station ids `r1-implement` and so on are gone, and the state line's `station=` becomes `node=`.
- Traversing a loop edge resets the counts of the loops nested inside it, which keeps "Prove fails per Round". As a side effect, notes on the Finish now reset Decide's extra-Round count.
- A spent loop raises a loop hold. Resume buys one more traversal, and the Steward may give one itself only on an edge marked for it.
- A Steward may edit a running Line's Plan only when that Plan allows it, and answers only the checkpoints and holds its nodes and edges hand it.
- A Conversation node hands on only once its Line brief has merged, and the engine reads that brief from the branch on every pass instead of recording it at End.
- `line.json` from before this ADR is refused at boot with a message to start a new Line. There is no migration.
