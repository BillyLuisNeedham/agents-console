# A finished pool's server stops from the Console, with a farewell

Once a pool reached `done` its server sat in the fleet until someone found the terminal it was launched from and killed it (issue #97, https://github.com/BillyLuisNeedham/agents-console/issues/97). The Console had no way to stop it, and nothing the server did on the way out told an open tab what had happened: `shutdown()` emitted no snapshot and dropped every stream, so a tab showed "pool · connecting" and retried forever, which is also exactly what a crashed server and a lost network look like.

We decided that the Console offers a "Stop server" button only while the pool phase is `done`, behind one inline "Really stop?" step (the End button's precedent; no modal), and that `POST /api/stop` refuses every other phase with 409: any other phase may have an attempt mid-flight or an answer about to be given, and a stale tab or a stray curl must not be able to end it. The route acknowledges with 202 before the stop begins, the way `/api/resume` acknowledges before processing, and the tab learns the stop landed from the stream.

The stream learns because shutdown now ends with a farewell: the run emits one last snapshot with a new terminal phase, `stopped`, before serving stops, and the server ends each snapshot stream cleanly behind it. The farewell lives in `shutdown()` itself, so a SIGTERM from a terminal sends it too. `stopped` is a new word rather than a reuse of `dead` because `dead` means the drive threw and carries an entry in `runs/errors.jsonl`; a stopped pool has done nothing wrong. A tab that has seen `stopped` shows it as such (with "from this page" on the tab whose request was accepted), shows the relaunch command, and keeps its usual retry so a relaunch from a terminal is picked up on its own.

An auto-stop timer after `done` was considered and rejected: a finished pool is where the operator reads the results, and a server that leaves on its own schedule takes the Console with it. A fleet-wide stop is out of scope.

**Consequences**: `RunPhase` has a sixth value, `stopped`, that only `shutdownSession` emits; the drive never does. The wire snapshot carries `poolDir` so the Console can print an exact relaunch command. The CLI's signal handler and the Console stop share one stop-then-exit path with its hard limit. Nothing changes for the fleet registry: prune-on-read still covers a stopped server's entry.
