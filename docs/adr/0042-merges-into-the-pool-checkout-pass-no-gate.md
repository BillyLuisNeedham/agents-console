# Merges into the pool checkout pass no gate

Amends ADR-0027 (`docs/adr/0027-keep-talking-continues-a-checkpointed-attempt-in-its-pane.md`) and ADR-0041 (`docs/adr/0041-one-rolling-scheduler-starts-each-ticket-once-its-blockers-merge.md`). ADR-0027 put a gate on every merge into the pool checkout. While a Continued attempt worked in the checkout, a merge waited at the gate and was recorded `merge-deferred`, and so did everything chained behind it, a Conversation's End merge, a verify round's grading and a queued merge answer included. Start the Line was refused. A boot chained every unsettled `merge-deferred` again. The gate existed because a lone Ticket ran in the pool checkout, so continuing it put an agent back in the tree that merges write to.

ADR-0041 gives every Ticket its own worktree, so a Continued attempt in a git pool works in a pool worktree. An enlisted pane in the pool checkout captures the merge target, and from then on merges land in the engine's merge checkout. A Continued attempt in the pool checkout of a git pool can now come only from events an older engine wrote. A pool outside git has no merges, so there the gate made grading and a Conversation's End wait for nothing.

We decided to delete the gate. Merges into the pool checkout run at once. The `merge-deferred` event kind, the boot's redo of deferred merges, and the waits in grading, a Conversation's End, Start the Line and queued merge answers go with it. The events reader already skips a line of an unknown kind, so a `merge-deferred` line an older engine wrote is ignored. A Ticket whose deferred merge that engine dropped at a shutdown boots Done and unmerged. It stands `stalled` in the Merge queue like any other Done Ticket a dead server left unmerged, for the operator to merge.

Keep talking's refusal stays. A Continued attempt in the pool checkout is still refused while another agent or a long-running engine job works there, because an enlisted pane in the checkout and every Attempt in a pool outside git still share one tree.

**Considered Options**: Keeping the gate with a reachable trigger was rejected. The only trigger left is a Continued attempt in the pool checkout, and putting one back there undoes ADR-0041's rule that the checkout is written only by merges. Keeping the boot redo for pools upgraded mid-run was rejected. It keeps an event kind and a boot pass alive for a state the current engine never writes, and the Merge queue already shows the Ticket as stalled rather than losing it.
