# Headless orphan attempts are killed, not adopted

Stopping the pool server left its headless harness children running (issue #65, https://github.com/BillyLuisNeedham/agents-console/issues/65). They reparented to init, kept spending, and kept editing their worktrees, while the relaunched engine, which held no record of them, reset their tickets to ready and spawned fresh attempts into the same directories: two writers, one tree. Restarts are routine because the pool config is parsed once at boot (issue #63), so this was the cost of every harness or model change.

We decided that a headless Orphan attempt is stopped by the engine, never adopted. The engine spawns each headless harness in its own process group and records the child's pid on the attempt's `spawned` event, beside the pane id a terminal-backed spawn records. On SIGTERM or SIGINT the server terminates every tracked group (TERM, a short grace, then KILL), lets the super-step join without raising crash interrupts, releases `runs/server.pid`, and exits. At boot, before the first scheduling, an in-progress ticket whose recorded pid is still alive in the recorded worktree is treated as an orphan from the previous engine: the engine stops it the same way, records the crash, and re-runs the ticket. A pid that is alive but not in that worktree is a reused pid, not an orphan, and is left alone.

The alternative was to make headless attempts survive a restart the way terminal-backed attempts do (ADR-0014): write the stream straight to the file instead of a pipe, take the exit code from a wrapper, and re-adopt the live process at boot. That would make a config-change restart lose no work, and it may still be worth doing. It was not chosen here because a headless child's stdout pipe dies with the engine, so its Stream file and derived log stop at the kill, and re-adoption would need the spawn path rebuilt first. Killing is the smaller change that removes the duplicate-writer hazard today; the parked worktree keeps whatever the orphan had done, and the re-run reads it.

Raising an interrupt at boot instead of killing was also considered and rejected: the engine cannot read a headless orphan's output, so the only answer a human could give is the kill the engine can perform itself.

**Consequences**: the runner skill's claim that "killing the server kills its harness" is now true. Terminal-backed attempts are untouched by shutdown; ADR-0014's re-adoption stands. The fleet registry still has no exit handler; a clean shutdown only removes the pool lock, and prune-on-read covers the rest.
