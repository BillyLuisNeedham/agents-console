# Attempts may run terminal-backed in herdr panes

A pool may set `terminal: herdr` so every spawn site — implement, resolver, grader, head-to-head — runs its attempt in a herdr pane (created via herdr's socket API in the attempt's worktree cwd, always `focus: false`) instead of a headless `Bun.spawn`. This is the engine half of the North Star (issue #29): every running agent is a real terminal the operator can watch and type into, while the engine stays oblivious to that input — an attempt still ends only on exit plus Outcome. Because herdr's API exposes no exit codes and bounds scrollback, the pane command is a wrapper shell string — `harness … 2>&1 | tee <stream-file>; echo ${PIPESTATUS[0]} > <exit-code file>` (bash, for `PIPESTATUS`) — writing the same files `spawnToLog` writes today. The engine waits on herdr's `pane_exited` event plus the exit-code file, and derives the live log by tailing the tee'd stream file with a follow-file reader feeding the existing streamlog derivation (ADR-0012). Files remain the source of truth; the pane is purely a viewport and input path. The `spawned` event records the `pane_id`; on boot the engine reconciles against herdr's snapshot — live panes are re-adopted, missing ones crash the attempt. Exited panes persist until their ticket merges, then the engine closes them. Herdr is optional: absent daemon or protocol mismatch falls the pool back to headless with a visible warning; it becomes the default once proven.

**Considered options**: building the Console's own PTY layer (node-pty + xterm.js) was rejected — herdr already solved PTY, scrollback, agent-state detection, and attach. Reconstructing logs from `pane.read` polling was rejected — worse fidelity than the tee'd files, and it would rewrite the ticket-log pipeline. Implement-only terminal backing was rejected — all spawn sites share one code path, and the North Star says *every* agent.

**Consequences**: if the herdr daemon dies, every pane dies with it — all in-flight attempts crash simultaneously and raise crash interrupts; accepted as no worse than the host rebooting today. The engine gains a second wait-path (event + file instead of child exit) and a follow-file tailer, but the log/Stream/Outcome contracts are untouched. The UI surface — open-in-herdr button vs embedded terminal — is deliberately deferred pending a prototype.

**Amendment (ADR-0015)**: the attempt-terminal unit is a named tab per attempt, not a bare pane: `tab.create` with label `<ticket-id> · <ticket-title>` (capped at 40 chars), `focus: false`, in the attempt's worktree cwd; the pane id is recovered via `pane.list` by tab id because `tab.create` returns none, and is recorded on the attempt's `spawned` event as `pane_id`.

**Amendment (ticket 01-spawn-1-spawn-1)**: two refinements to the close lifecycle and the daemon-death story above. First, "exited panes persist until merge, then the engine closes them" only ever fires for attempts whose ticket merges; grader, head-to-head, and losing verify-candidate tickets never merge, so their tabs would accumulate in the operator's tab bar across verify fan-outs. The close rule is now: a tab closes the moment its attempt's role ends. For merging attempts that is the merge; for grader tabs the grade landing (or the grader's recorded failure); for the head-to-head tab the judge's verdict; for losing candidates the selection's loser discard. All closes stay best-effort and keyed off the tab id on the attempt's `spawned` event. Deliberately left open: a flagged lone attempt's tab (verify:1 checkpoint; the human may want to inspect the terminal before deciding) and crashed ordinary attempts. Second, daemon death no longer crashes every in-flight attempt at once: when the pane-end subscription is lost (socket error or close, e.g. a daemon restart) the pane wait settles as "lost" and the engine falls back to an unbounded poll of the wrapper's exit-code file, unbounded the way the headless spawn's wait on its child is unbounded. The attempts ride out the outage instead of raising crash interrupts in unison; if the daemon's death killed the pane's harness, recovery is the operator's, since nothing will write the exit-code file.
