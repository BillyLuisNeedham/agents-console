# Keep talking continues a checkpointed Attempt in its pane

A Terminal-backed attempt that ends in a checkpoint leaves its TUI running (ADR-0016: the TUI stays alive after its Outcome), with the whole conversation that led to the checkpoint in it. Until now the Console dropped that pane the moment the Attempt ended: the Live attempt left the registry, so the card lost its Peek, its "Open in herdr" and its attach line while the Interrupt was still waiting, and the only answer was Resume, which launches a fresh Attempt in a new tab with a Brief and a Resume note for context. The agent that actually held the context sat idle beside it, and when the new Attempt was solo it shared the ticket's well-known Outcome and exit-code files with the old one (issue #139, https://github.com/BillyLuisNeedham/agents-console/issues/139). Very often the operator's answer to a checkpoint is a conversation, not a note: "yes, but" and "what about", with the agent that asked.

We decided that a checkpointed Attempt's pane stays the pool's while its checkpoint Interrupt waits, and that the operator can **Keep talking** to it. The pane is a **Held pane** (CONTEXT.md): the engine holds it wherever a checkpoint Interrupt is raised over an Attempt whose `spawned` event names a pane (the agent's own checkpoint, a lone verify attempt's flagged grade or blocked merge, a selected winner whose merge conflicted), reads it back from the latest `checkpoint` event after a restart, and shows it on the snapshot only while herdr still lists the pane. Peek, focus and attach serve it exactly as they serve a Live attempt's pane, so ADR-0021's rule that the Console reaches only panes the engine registered still holds: a Held pane is the engine's record. An enlisted pane is never held, because it is the operator's own terminal and they can simply talk to it there; a merge-conflict, merge-approval or selection Interrupt holds nothing, because none of them was raised by the Attempt whose pane it would be.

Keep talking starts a **Continued attempt**: a new Attempt, with its own number and its own Outcome, launched into the existing pane rather than a new tab. Reopening the ended Attempt so it could take a second Outcome was rejected: an Attempt ending is a recorded fact (the `exited` event, the Brief, the grade), and taking it back would make every reader of the events file ask which ending of an Attempt it is looking at. The Continued attempt's `spawned` event names the same pane and tab, `continued: true`, the Attempt it continues, the Attempt whose worktree and branch the work lives in, the Stream file the pane's `script` is still writing and where that file stood, so its log is its own part of the session and a restart can re-derive it.

It starts **at once**: not queued to the super-step boundary and not held by the Merge hold. That is an exception to ADR-0004, with Enlist (ADR-0021) as its precedent. ADR-0004 queues answers because processing mid-super-step races the join, spawns in the main checkout and merges; Keep talking does none of those. It launches nothing, opens no worktree, merges nothing, and changes one ticket that no super-step in flight is running. Its claim is synchronous (the checkpoint Interrupt answered, the marker in-progress, the next Attempt number, the `spawned` event, the Live attempt registered on the same pane), so no answer, boundary or second Keep talking lands halfway through it. What does need the boundary waits for it: the Continued attempt's ending is recorded off the drive the way an adopted attempt's is (merges chained onto the session merge chain), and a verify ticket's grading runs in the drive loop between super-steps. While a Continued attempt works in the pool checkout itself, every other ticket is given a worktree, so the drive never launches a second agent into its tree. A pool whose only unfinished work is a Continued attempt settles quiescent, not stalled, and keeps its store open for the ending.

The engine types **one teaching Turn** (`buildContinuedTeaching`), once the pane's Turn state is waiting and never mid-reply, bounded as an enlist's is, and then leaves the pane to the operator. The agent already wrote the Outcome it was asked for and believes its part is over, so the Turn says the operator chose to carry on here, that the old Outcome is spent, and restates the whole Outcome contract with the exact path; the checkpoint's Outcome file is removed before the watch is armed so it can never be read as the new one. A pane that will not take the Turn ends the Continued attempt at once as a checkpoint of the engine's own saying so, still over the same pane, rather than leaving a ticket running on an agent that does not know it owes an Outcome. The ending is an enlisted attempt's two-form race, a valid Outcome on disk against the pane leaving herdr's listing: the wrapper's exit-code file belongs to the Attempt before and lands only when the TUI closes, which the pane leaving already says. Outcome done ends the ticket as any done does (the merge chain on a solo ticket, grading on a verify one); Outcome checkpoint raises a fresh Interrupt with the new Brief over the same pane, which can itself be continued; a pane gone with no Outcome is a crash, as it is for any terminal attempt.

The Continued attempt runs under **the pane's Assignment**, the checkpointed Attempt's own as its `spawned` event recorded it (every `spawned` event now carries the harness and model it launched with), whatever a Reassign has written since, because that is the agent in the pane. It is frozen across a config reload while it runs, like an adopted or enlisted attempt's, and the ticket goes back to the config's Assignment at its ending. On a `verify: N` ticket the Continued attempt runs alone and is **graded as a lone attempt**, verify: 1 semantics whatever N is: there is one agent in one pane, nothing to fan out or select between. A flagged grade becomes a checkpoint Interrupt over the same pane, so it too can be continued; a pass merges the branch the chain has been working on. Its files are attempt-numbered as the Attempt it continues was, and grading follows it back to that Attempt's worktree and branch. A Continued attempt still live when the engine stops is re-adopted at boot like any Terminal-backed orphan, adoption interrupt included, with its own runtime and no second teaching Turn; answering the adoption interrupt abandons it and closes the pane, as for any adopted attempt.

**Plain Resume closes the old pane.** When a ticket's fresh Attempt launches after its checkpoint was answered with Resume, the engine first closes the tab of the checkpointed Attempt, so two agents never share the worktree and a solo ticket's well-known Outcome and exit-code files. It is derived from the events (the latest tab-bearing `spawned` event with a `checkpoint` after it), so a Resume answered before a restart still closes its tab after it, and it never touches an enlisted pane. This narrows the "deliberately left open" clause of ADR-0014's close-on-role-end amendment for checkpoints only: a crashed attempt's tab still stays open.

Tabs otherwise **close only on the operator's word**. A crashed attempt's tab, a done ticket's tab waiting on its merge or run in a pool with nothing to merge, and every other tab the pool opened over an Attempt or Conversation that has ended accumulate in herdr's tab bar, and so does a started Conversation's tab after a Stop or Restart, which the next boot marks crashed without a word to herdr. These are **Finished terminals** (CONTEXT.md), derived and never recorded: the tabs every `spawned` event names, less the ones herdr no longer lists, less any tab over a pane still in use (a Live attempt's, a Held pane, a live Conversation's), with enlisted owners left out before their events are read. The pool header offers "Close N finished terminals" behind the same inline confirm Stop uses, and the engine closes the set it derives afresh at that moment. Every close the engine makes by rule stays best-effort, but none is silent any more: a tab herdr refuses to close lands as a `tab-close-failed` event on its owner's log and a pool log line naming the error, where a swallowed catch used to hide why a tab stayed open. Closing Finished terminals automatically, at a pool's done or on a timer, was rejected: a finished terminal is often exactly what the operator wants to read next (the crash, the last thing the agent said), and nothing is lost by leaving it open.

Whether a Held pane or a finished tab is still there is the **pane survey**'s to say: one daemon-wide `pane.list`, cached, on a slow cadence (15 s) and on demand whenever the engine holds a pane, continues one, or closes the finished set. The snapshot reads the cache and never herdr, and a listing emits only when what the snapshot derives from it moved, because the snapshot is emitted far more often than panes come and go.

**Consequences**: a checkpoint no longer ends the engine's interest in a pane, so the Console's pane surfaces key off "the ticket's pane" (a Live attempt's or a Held one) rather than the Live attempt alone, and a Held pane is also one the enlist picker refuses. The ticket log gains Attempts with no Stream file of their own, whose log is a slice of the Attempt before's typescript. The survey is a new, bounded herdr cost of one listing per cadence per pool. Held panes are not persisted; a restart finds them again from the events and the survey. Keep talking is offered only where a pane exists, so a headless pool never sees it.
