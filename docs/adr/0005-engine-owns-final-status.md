# The engine owns the final status write

A ticket agent works in a worktree, but the Issue whose line-1 marker records its status lives in the main checkout. Agents whose tools default to cwd-relative paths sometimes edited the worktree copy instead; the engine's read-back of the canonical Issue then saw `in-progress` and recorded a crash for an attempt that had finished cleanly. Resuming re-ran the same prompt, the agent repeated the same slip, and a ticket could ping-pong crash/resume forever, with the human unable to tell a dead harness from a finished ticket without reading logs. This was issue #18 (https://github.com/BillyLuisNeedham/agents-console/issues/18); the design is `docs/specs/2026-08-30-engine-owns-final-status.md`.

We decided the agent never writes the Issue's status at all. The attempt signals its ending through the Outcome JSON it already writes at exit (`done` or `checkpoint`, with the Brief travelling in the same file), and the engine writes the final status to the canonical Issue itself, at attempt exit, exactly where read-back ran.

Three alternatives were weighed. Read-back falling back to the worktree copy (issue #18's fix option 1) patches the symptom but keeps two writable copies of protocol state, so the next relative-path slip becomes a silent fork rather than a visible crash. Prompt-only wording (instructing agents harder to use the absolute path) changes nothing structural: the slip is invisible from inside the worktree, so the agent cannot catch itself, and the crash/resume loop survives. Symlinking the canonical Issue into worktrees (fix option 3) makes worktree edits land on the canonical file, but couples the protocol to symlink behaviour across harnesses and filesystems, and still leaves protocol state in the agent's hands at all.

The structural fix was chosen because it deletes the false-crash class rather than patching it: a relative-path slip can now cost the agent its notes, never its status. The cost is a state-protocol change and a one-crash cutover. Agent-written marker statuses are no longer honored anywhere, so every pool's standing instructions change in the same commit, and an attempt in flight when the new engine first runs crashes at most once; resume re-spawns it under the new protocol, reuses the parked worktree, and finishes.

**Consequences**: crash interrupts now mean the attempt genuinely failed (non-zero exit, missing outcome, unparseable outcome, or an invalid status value), and the crash event carries a distinct reason for each. A checkpoint's Brief is appended to the canonical Issue by the engine, with a placeholder when the outcome omits it, so the interrupt body always survives a server restart. Marker read-back as an ending signal is removed; rehydration still treats on-disk markers as truth, so restarts remain boring.
