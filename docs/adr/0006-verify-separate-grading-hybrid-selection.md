# Verify: separate grading with hybrid selection

Verification was inspired by the llm-as-a-verifier paper, but we deliberately did not copy its absolute-score selection. Separate grading calls give noisy scores — a "7" graded in one call is not comparable to a "7" graded in another, because each grader sees only one Attempt and has nothing to calibrate against. So the engine grades each Attempt alone, takes the winner outright when its margin is ≥2 points, and pays for a head-to-head side-by-side comparison (the paper's pairwise style) only between the top two when the spread is tighter. Plain score with the pool's existing model, not the paper's logprob-expectation trick — that needs a logprob-capable endpoint (DeepSeek API, Vertex Gemini, vLLM) and was deferred until plain scores prove too coarse. Verification is per-ticket opt-in via a single `verify: N` key (N parallel attempts, N grader tickets, then selection) — no pool-level enable, and the absence of the key is exactly today's behavior. Graders are first-class tickets rather than harness internals, so grader harness and model are chosen through the ordinary assign machinery; a grader crash re-spawns a fresh grader instead of passing or failing the build ticket. Merge-resolver attempts are out of scope for v1.
