# Agent-authored text is a claim; the engine judges it against what it observed

Verify exists because an agent's own account of its work is not enough to act on (`CONTEXT.md`, Verify). The rule that makes it work is one line of prose: "The log is evidence. The summary is a claim. When they disagree, the log wins" (`skills/my-console-runner/verify.template.md:21`). That line is an instruction handed to a grader agent, and it is the only place the comparison is written down. The nearest thing to it in a decision record is ADR-0014 (`docs/adr/0014-attempts-terminal-backed-in-herdr.md:17`), which says the Outcome is the agent's account of itself and the exit code is evidence, and the only statement of it in the engine is a comment saying a marker status an agent wrote is never honoured (`engine/engine.ts:154-158`). Everywhere else the principle is assumed rather than stated, and claimed text already travels a long way on that assumption: an Outcome summary goes verbatim into the next agent's prompt (`engine/prompt.ts:311`) and into the Review interrupt body a human approves (`engine/engine.ts:5842`), a Grade's reasons become the Brief of a checkpoint (`engine/engine.ts:5173-5181`) and the body of a selection interrupt (`:5381-5384`), and a resolver's `resolved: true` self-report picks which merge path runs (`:4054-4062`). Issue #109 (https://github.com/BillyLuisNeedham/agents-console/issues/109) now replaces the grader agent with a Jev call, which removes the one place the rule is written; and the TypeSafe docs are explicit that Evidence is not treated as hostile, so text arguing for its own classification can move an answer, which is exactly what a confident summary is. Issue #114 and the pool's `AGENT.md` already state that agent-authored text is untrusted input to Jev, but ADR-0020 (`docs/adr/0020-jev-gates-paths-engine-writes-status.md`) deliberately landed only the gating half of that rule.

We decided to classify text by who wrote it rather than by what it says. Text is **observed** when the engine or the harness produced it: the attempt log, the diff at the commit, the exit status, the sha the engine read back with `commitShaAt`. It is **claimed** when a spawned agent wrote it: the Outcome summary and its `commitSha`, a Brief, a Grade's reasons, a spawn title and body, a resolver's note. Three rules follow. Every Evidence object a call site builds names the two separately, and claimed text sits in a field of its own rather than being joined into the question's instructions or criteria, so it is data being judged and never direction being followed. Where the two disagree about the same work, the observed wins, and that stops being prose: on the Jev path the engine asks for it as a judgement of its own, at least one narrow question whose whole job is whether the claim matches the observation, and the engine applies the consequence rather than leaving a weighted score to absorb it. And where an engine decision needs a sentence a person will read, the engine composes that sentence from the typed answers it holds rather than borrowing an agent's prose. That last rule is forced on the Jev path, because Jev never generates text, and it has teeth: composed reasons are what a checkpoint Brief and a selection interrupt will carry.

The alternatives were to leave the rule in the rubric prose, which fails the moment a pool has a key because `verify.md` stops being read on that path; to rely on Jev's calibration to see through a confident summary unaided, which the docs say it will not reliably do; and to sanitise claimed text before it reaches Evidence, rejected because spotting an injected instruction by matching strings is the class of fragility issue #114 exists to remove. Consequences: no Jev call site exists on any production path today, the port is constructed and logged but idle, so this rule is set before the sites that must obey it are written, which is the point of writing it now; every such site will carry at least a two-field Evidence shape, so a reviewer can check the rule by reading the field names; the grading question set for #109 has to carry an explicit claim-against-log judgement rather than one composite score, which narrows that design before it is built; `verify.template.md` keeps its prose because the fallback grader still reads it, so the same rule now lives in two forms and has to be kept in step; and the pair of terms, Claimed and Observed, enters `CONTEXT.md`. The rule constrains how agent text reaches Jev, not what Jev may be asked, so the room to experiment that ADR-0020 preserved is untouched. It says nothing about the paths that read claimed text today without a judgement at all, `prompt.ts:311` and the resolver among them; those are issue #112's ground and later work, not this decision's.
