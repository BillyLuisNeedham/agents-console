# Conversations are a first-class concept beside Tickets

Issue #60 (https://github.com/BillyLuisNeedham/agents-console/issues/60) asks to use the Console to talk to many agents at once: hold a long, open-ended talk with one agent, have it start other agents mid-talk — some doing work, some more talks — learn in the parent talk when a worker finishes, and see at a glance which of the many talks is waiting on the operator. Terminal-backed attempts (ADR-0014, ADR-0016) give us a real TUI the operator can type into, but every unit the engine runs today is a Ticket: it must end in an Outcome (done or checkpoint), a checkpoint answer restarts it as a fresh Attempt rather than continuing the talk, and nothing tells one attempt that another one finished.

We decided a **Conversation** is a new first-class concept in the Pool, beside Ticket, not a kind of Ticket. A Conversation has an Assignment fixed at start, its own worktree and branch, runs as a terminal-backed TUI in a herdr tab, and has no done condition: only the operator ends it. While it runs its agent may Spawn Tickets and Conversations through the same propose-and-adopt seam as ADR-0010, and when something it spawned ends the engine types a **Notice** into the parent as a Turn. Turn state (working vs waiting on the operator) is detected from the harness's idle prompt. On End, the branch merges through the existing merge-approval and merge-resolver machinery; a Conversation never holds the scheduler, is never verified or graded, and cannot be named in a Ticket's blockedBy.

The alternative was an open-ended Ticket kind — a Ticket whose Outcome may never arrive, with the interrupt loop re-purposed as the talk. It was rejected because every Ticket invariant would need an exception: Outcome-completes-the-attempt (ADR-0016), Merge hold on done-but-unmerged tickets (ADR-0014), Verify's N-attempts-one-grade shape, the ready-set computation, and the checkpoint-answer-restarts-attempt rule (ADR-0004). Each exception is a place where a talk could accidentally be scheduled, graded, or held like work. A second alternative, a plain list of herdr tabs with no engine involvement, gives the multiplexing but none of the spawn, notice, or turn-state features, which are the point.

**Consequences**: the Pool gains a second collection with its own lifecycle, storage, and card lane; the server exposes Conversations as their own resource rather than as tickets with a flag. Spawn proposals gain an optional Assignment and may originate mid-run, not only from an Outcome, so the adoption seam is now polled for proposals while a Conversation is live. The run-wide Spawn cap does not apply to Conversation Spawns (per-proposal cap of five stays). Notices are typed into the pane, so the engine's readiness and echo machinery from ADR-0016 is reused for delivery, and a Notice typed while the operator is mid-sentence is an accepted v1 hazard; a Console-side input box remains the fix if it bites. Crashed Conversations are terminal in v1 (branch kept, no resume); persistence and resume, talking inside an existing Ticket's worktree, Console-side typing, and letting a parent's agent answer a child's Interrupt are all explicitly deferred.

**Amendment (issue #102, Botched launches)**: "branch kept, no resume" applies to a Conversation that crashes after it went live, where the operator may have work on the branch. A Conversation whose Launch never produces a running harness — the wrapper command never ran on any try, the TUI never became ready, the opening Turn never landed, or the harness died before its TUI came up — is recorded `crashed` for the event trail and so its id is never reused, but its worktree is removed and its branch deleted: nothing ever ran in them, and a pool where launching is a coin flip would otherwise collect an orphaned pair per failure. The Launch itself is retried into fresh tabs (up to three) before it counts as a crash, for Conversations and Ticket attempts alike, and a Botched launch is never graded.
