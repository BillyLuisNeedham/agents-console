# Assignments are resolved server-side and served on the snapshot

Issue #35 asked the Console to show which harness and model each ticket runs on. The engine already resolves every ticket's assignment (field-wise assign overrides over pool defaults, with grader, head-to-head, and spawned tickets inheriting from their build or parent ticket) but kept the result in `Session.assignments`, off the wire — so the prototype re-derived it in the UI from `snapshot.state.config`. Two derivations of the same rule is the drift ADR-0007 already burned us on with the winner. The decision: the engine's resolved assignments go on the snapshot as one `{ harness, model, drivers }` record per ticket, and the card badge renders that record verbatim — no source labels, no client-side resolution. The UI stays a dumb renderer of the engine's single derivation.
