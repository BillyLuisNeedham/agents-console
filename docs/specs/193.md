# A Factory can start from any branch, not only main (issue #193)

## Problem

Boot's Factory mode cuts `line/<slug>` only from `refs/heads/main` or `refs/remotes/origin/main`, and refuses when neither exists ("has no main branch (local or origin/main) to cut the Line's branch from"). A repo whose trunk is `develop` (android-app) cannot run a Factory, and neither can a Line that belongs on top of a long-running branch (`experiment/android-map-ios-og`, checked out in its own worktree and pushed to origin). Once the cut is made, the ref it came from is printed and lost, so everything downstream assumes `main`.

## Where main is assumed today

- `crates/cli/src/boot/factory.rs:177-184` `main_ref`, and `cut_line` (:210-240), which returns `CutLine.from` but nothing keeps it. Boot prints `line: cut {branch} from {from} at {worktree}` at `crates/cli/src/boot/mod.rs:1195`.
- `crates/cli/src/boot/mod.rs:52-69` `FACTORY_HELP`: "cuts line/<slug> from main".
- `crates/core/src/line.rs:1226-1231` `review_ticket`: "the changes since it left main".
- `crates/core/src/line.rs:1314-1354` `finish_act`: `gh pr create --base main`, and the comment at :1335 says the Line is "cut from main".
- `docs/adr/0038-*.md`: "cut from main".
- `LineState` (`crates/protocol/src/wire.rs:1962`, saved as `<pool>/line.json`) and `LineBrief` (`wire.rs:1920`, `deny_unknown_fields`) have no base.

## Decisions (all final, settled at the Grill)

1. **The Line base.** This new glossary term (already in `CONTEXT.md`) means the branch a Line was cut from and the commit it was cut at. Boot chooses it once, and it never changes afterwards.
2. **Where it lives.** Boot writes it into the pool's `console.json` as `lineBase: { ref, commit }` next to `factoryPool`. `ref` is the name Boot cut from as resolved (`experiment/x` or `origin/experiment/x`). `commit` is the full SHA it pointed at. When the Line starts (`start_line`, `crates/engine/src/line.rs:134`), the engine copies `lineBase` into a new `LineState.base: Option<LineBase>` (`{ ref, commit }`) beside `branch`. Restart already re-reads both files, so the base survives it. The Line brief never carries the base. Regenerate `protocol/*.ts` (`cargo run -p ac-protocol --bin gen-typescript -- protocol`).
3. **Default cut: the current branch.** Without `--from`, Boot cuts from the branch the checkout has out (`git symbolic-ref --short HEAD` of the cwd's checkout). The `main` / `origin/main` lookup is removed. On a detached HEAD, Boot refuses and says to check out a branch or pass `--from`. Booting from a feature checkout therefore cuts from that feature branch, not `main`; this is intended.
4. **`--from <branch>`** on `agent-console --factory` (and with `--brief`) overrides the default. It takes branches only, resolved in this order: `refs/heads/<name>`, then `refs/remotes/<name>` (so `origin/x` works as written), then `refs/remotes/origin/<name>`. Tags, SHAs and anything else are refused with a message naming what was tried. Boot never fetches; it uses the refs as they are. `--from` without `--factory` is refused like the other Factory-only flags. The base does not need to be checked out anywhere, and nothing checks whether it is: `git worktree add` cuts from a branch checked out in another worktree.
5. **No upstream tracking.** Boot always cuts with `git worktree add --no-track -b line/<slug> <dir> <ref>`. The Line's branch then never tracks its base: a bare `git push` creates and tracks `origin/line/<slug>` (push.autoSetupRemote), and can never land on the base.
6. **Boot says what it cut from.** The line becomes `line: cut line/<slug> from <ref> (<short commit>) at <worktree>`. Update the help text to say the Line is cut from the current branch, or from `--from`.
7. **The Grill hears it.** `grill_opening` (`crates/cli/src/boot/factory.rs:155`) adds a sentence naming the Line base, for example "This Line was cut from `experiment/x` at `abc1234`." `grill_teaching` (`crates/core/src/line.rs:1540`) documents the brief's new `pushBase` field (decision 10) and tells the Grill to ask the operator about it only when the Finish is `pr` or `draft-pr`.
8. **Review diffs from the cut commit.** `review_ticket` names the base and its commit: "the changes since it left `<ref>` at `<commit>`: `git diff <commit>..HEAD`". The commit never moves, so a base that is force-pushed, rebased or deleted mid-Line cannot change what Review sees. (No Station ever merges the base into the Line.)
9. **The PR's base.** For `pr` and `draft-pr`, `finish_act` names the PR base: the Line base's branch name on origin, i.e. `ref` without a leading `origin/`. It opens with `gh pr create [--draft] --base <name> --head line/<slug>`. Decide checks origin when the Finish runs (`git ls-remote --heads origin <name>`), not at the cut, and acts per the table below. Only `origin`, never another remote.
10. **The push grant: `pushBase`.** `LineBrief` gains an optional `pushBase: bool`, default false. The engine writes whether it was granted into the Finish text, so Decide never infers it from prose. With the grant, Decide may create the base on origin or fast-forward it, and never force-push:

    | origin's state | `pushBase: true` | no grant |
    | --- | --- | --- |
    | no `<name>` on origin | push the base to create it, then the PR | no push, no PR; say why in the report and the Outcome, as the not-a-Line-branch case does |
    | origin's `<name>` equals the local base | the PR | the PR |
    | local base is ahead (fast-forward) | push the base, then the PR | the PR, and note in the report that it carries the base's unpushed commits |
    | diverged (would need a force-push) | no push, no PR; say why | same |

    "The local base" means the local branch `<name>` when the Line was cut from a local branch. When the Line was cut from `origin/<name>`, origin already has it, so that case is the middle row.
11. **ADR-0038 amended in place.** "Cut from main" becomes "cut from its Line base". The consequence now reads that the only branch other than its own a Factory pool may push is its Line base, only under `pushBase`, only creating or fast-forwarding it, never forcing. (Already done on the Grill's branch.) No new ADR.
12. **Lines started before this change** have no `lineBase` and no `LineState.base`. They read as `main` with no commit. Review says "since it left main" as today, and the PR base is `main`. A Line started by hand (`POST /api/line/start`) in a pool with no `lineBase` behaves the same way.

## Acceptance criteria

1. `agent-console --factory --from experiment/x --work "…"` in a repo with a local `experiment/x` cuts `line/<slug>` from it. It prints `line: cut line/<slug> from experiment/x (<short>) at …` and writes `lineBase: { ref: "experiment/x", commit: <sha> }` into `console.json`.
2. `--from origin/experiment/x` (remote-tracking only, no local branch) cuts from it. `--from experiment/x`, with only `origin/experiment/x` present, resolves to `origin/experiment/x`. In both cases `git config branch.line/<slug>.remote` is unset (no tracking).
3. `--from` naming a tag, a SHA or a missing branch is refused, and no worktree or branch is created.
4. Without `--from`, Boot cuts from the current branch, including in a repo with no `main` (the existing refusal case for a repo on `trunk` becomes a success that cuts from `trunk`). A detached HEAD is refused.
5. The base can be a branch checked out in another worktree.
6. Starting the Line copies `lineBase` into `line.json`'s `base`, and it is still there after a Restart.
7. The Review Ticket's body names the base ref and its commit, and contains `git diff <commit>..HEAD`.
8. A `draft-pr` Finish on a Line cut from `experiment/x` has Decide's text name `--base experiment/x` and `--draft`. A Line cut from `origin/experiment/x` also names `--base experiment/x`.
9. The Finish text states the grant: with `pushBase: true` it allows creating or fast-forwarding the base and forbids a force-push. Without the grant it forbids pushing the base and says to open no PR when origin lacks it. A brief with `pushBase` parses, and one with an unknown field is still refused.
10. A Line whose `line.json` has no `base` keeps today's texts (`main`).
11. Conformance cases (ADR-0036, importing only from `protocol/`) cover 1, 2 (both forms, plus the no-tracking check), 3, 4 (no main, and detached HEAD), 5, 6, 7, 8 and 9. Add a bare `origin` repo to the CLI harness world (`conformance/harness/cli.ts`, `cliWorld.repo()`) for the remote-tracking cases. Update the existing cases that expect `from main` (`cli-boot-factory.test.ts`, `factory-finish.test.ts`, `factory-grill.test.ts`) to the new behaviour.
12. Unit tests cover `--from` resolution, `finish_act` for every row of the table's texts, and `review_ticket` with and without a base.
13. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` pass.

## How Prove shows it working

From the repo root:

1. `cd ui && ~/.bun/bin/bun install && ~/.bun/bin/bun run build && cd ..`, then `cargo build --release`.
2. `cargo test`, then the Factory conformance cases only: `~/.bun/bin/bun run conformance conformance/cases/cli-boot-factory.test.ts conformance/cases/factory-finish.test.ts conformance/cases/factory-grill.test.ts conformance/cases/factory-line-start.test.ts`.
3. End to end in a scratch repo with a bare origin: create `develop` and `experiment/x` (no `main`), and check `experiment/x` out in a second worktree. From a checkout on `develop`, run `target/release/agent-console --factory --from experiment/x --brief <a brief>` (or `--work`). Show the `line: cut` line, `console.json`'s `lineBase`, `git config branch.line/<slug>.remote` (empty), and `line.json`'s `base` after the Line starts. Then show the Review and Decide Ticket bodies naming the base. A real `gh` PR is not required.

## Out of scope

- Plain (non-Factory) pools, and `crates/io/src/git/repo.rs`'s fallback to `"main"` on a detached HEAD.
- Fetching before the cut, remotes other than `origin`, and showing the base in the Console UI (the Line strip stays as it is).
- Rebasing or merging the base into a running Line.
