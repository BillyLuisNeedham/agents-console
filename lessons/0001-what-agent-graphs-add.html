Lesson 1 · Agent graphs

What agent graphs add

A graph makes an agent system’s control flow, state, and pause points explicit. By the end, you should be able to tell whether that explicitness solves a real problem in your current workflow.

The one-sentence idea

An agent graph is an executable state machine for agentic work. Nodes do pieces of work. Edges decide what happens next. State carries what the run knows. A graph runtime can persist that state at each step so execution can pause, resume, branch, loop, and be inspected.

This is the model used by LangGraph: state, nodes, and edges; execution proceeds in message-passing “super-steps.” LangGraph Graph API

First, clear away two false pictures

Not a knowledge graph This is not primarily about entities and relationships stored in a graph database. It is about control flow: which piece of software runs next.
Not automatically autonomous A graph can encode a rigid workflow, a model-directed agent, or a mixture. The graph is the container, not the intelligence.
Not always worth it Anthropic’s guidance is to start with the simplest solution and add agentic complexity only when it demonstrably improves outcomes.

The four parts to look for

State The run’s memory: request, clarifications, plan, artifacts, errors, retry count, and approval status.
Nodes Functions that do work. A node may call an LLM, invoke a tool, run tests, write files, or ask a human to approve something.
Edges Routing rules. Some are fixed; others inspect state and choose between continuing, looping, branching, or stopping.
Checkpoints Saved snapshots at step boundaries. They make long-running work resumable and make human approval practical.

LangGraph calls the shared data structure State, the functions Nodes, and the transition functions Edges. Nodes return partial updates, and reducers define how those updates merge into state. Graph API

Map it to your Skillflow

You already get some graph benefits socially and procedurally: specialized agents, narrow context windows, artifacts between steps, and human review. A graph runtime changes where those rules live.

Today: handoff convention One agent finishes and hands a narrow packet to the next agent through your process.
Graph: typed state channels The packet becomes explicit state. Reducers decide whether updates overwrite or accumulate.
Today: runner decides next Your shell runner, ticket queue, or human session chooses the next specialized agent.
Graph: executable routing A fixed edge, conditional edge, or node command chooses the next node from state.
Today: context lives in files Specs, tickets, and notes preserve state outside the context window.
Graph: checkpointed threads A runtime can snapshot state and resume the same thread after failure or approval.

The real benefit

The graph is not valuable because it is shaped like a graph. It is valuable when you need durable, inspectable control over work that branches, loops, pauses, or runs in parallel.

That is why LangGraph emphasizes durable execution, persistence, streaming, and human-in-the-loop rather than hiding prompts behind a high-level agent abstraction. LangGraph.js overview

About the Karpathy reference

You probably mean Andrej Karpathy. His autoresearch project is a useful example of an autonomous engineering loop: an agent edits code, runs a measurable experiment, keeps or reverts the change, and records what happened. The important lesson is not “put everything in a graph framework”; it is that autonomous loops need verifiable feedback, bounded scope, reversible actions, and state that survives outside the model’s context window.

When a graph earns its keep

Use one when You need cycles with guardrails, approval gates, resumable long-running work, parallel fan-out, subgraph composition, or time travel through state.
Skip one when A fixed sequence of function calls, a single prompt chain, or one ordinary tool-calling loop already solves the problem reliably.

Anthropic’s workflow patterns — routing, parallelization, orchestrator-workers, and evaluator-optimizer — can all be represented as graphs, but none of them requires a graph framework by definition. Building effective agents

Five-minute mapping exercise

  1. Write down the nodes in your current grill → spec → tickets → implement process.
  2. List the state that must survive each handoff. Distinguish durable artifacts from temporary context.
  3. Write one routing rule as a sentence: “If state has ___, go to ___; otherwise go to ___.”
  4. Mark the first place where you would want a human approval interrupt.
  5. Decide whether a checkpoint would add something your current files and runner do not already give you.

Reply to the agent with your mapping and ask it to critique the graph boundaries. Ask follow-up questions whenever a term still feels fuzzy.
