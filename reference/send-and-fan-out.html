Send and fan-out

When work splits, what does each worker see, and how do the writes come back together?

Same-snapshot fan-out Multiple normal edges, or a conditional edge returning node-name strings. Every destination runs in the next super-step and reads the same starting state.
Send new Send(nodeName, args). Schedules one invocation of that node whose input is args, not the shared snapshot. Count and payloads are decided at runtime.
Map The list of Sends. One task per item, private input, all concurrent in one super-step.
Reduce The reducer on the channel those tasks write. Required: a last-value channel throws on concurrent writes.
Fan-in A node with an edge from the mapped node runs once after that super-step, seeing the reduced state.
Command.goto Can hold node names or Sends. Returned from a node, optionally with update. Do not also attach a static edge from the same node.

Rules that bite

  • Target must be an addNode name. Not validated at compile. Not END.
  • Parallel writes to one channel need a reducer. Concat order is not guaranteed — key the items.
  • One thrown task discards the super-step. Checkpointer: successful tasks stay done; retried nodes start over.
  • Recursion limit counts super-steps. A thousand Sends is one step.
  • Dependent work is a normal or conditional edge, not a Send.

Minimal shape

(state) => state.items.map((item) => new Send("work", { item }))
